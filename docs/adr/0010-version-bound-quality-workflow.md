# ADR 0010：版本绑定的独立审查与有限修复

日期：2026-09-09。状态：已采纳，离线与隔离进程验证；真实模型验收另记。

`workflow.start` 在已成功的实现任务上启动核心持有的质量流程。请求必须给出 `idempotency_key`、`target_paths` 与确定性 `checks`，可将 `auto_repair` 设为 false。`workflow.evaluate` 继续作为评价接口；对已启动的流程只能读取、核对已绑定的条件，不能接收调用方自报的审查结论或降低检查要求。

目标是明确选择的 UTF-8 普通文件，最多 64 个、内容合计 256 KiB，完整审查/修复提示词另限 96 KiB。文件相对路径、内容 SHA-256、权限模式、缺失状态，以及存在 Git 仓库时的 HEAD 共同构成目标哈希。路径逐级使用目录描述符与 no-follow 打开，拒绝符号链接、二进制、状态目录和 `.git` 内容。非 Git 目录使用同一文件快照协议。验收仅覆盖 `target_paths`，不声称审过整个仓库、依赖或未选择的文件，也不将局部文件快照称为完整 Git diff。

流程按检查、审查、修复、重新检查推进。审查是独立 run 和 conversation，拥有单独后端引用；不续接实现者的会话。首个真实适配入口是 Claude 的一次性快照审查，fake 提供显式模拟。Codex/Grok 的审查权限配置尚未适配，作为 reviewer 时会暂停，只有配置中明确的可执行 `approved_substitute` 才能替代。真实实现后端不能以 fake 审查者降低质量要求。独立调用/会话不等于不同模型、不同账户或已验证的审查质量。

Claude 审查子进程使用临时空目录，只接收所选快照；以 `--tools ""`、`--disallowed-tools "*"`、`dontAsk`、空且严格的 MCP 配置、空用户/项目设置来源、禁用 slash commands、Chrome 和会话持久化运行。通过 `disableAllHooks` 禁用非受管理 hooks；不使用会改变认证路径的 bare 模式，也不隐含切换付费 API。参数依据本机 Claude 2.1.154 的 help 和[官方 CLI 说明](https://code.claude.com/docs/en/cli-reference)。这些是适配器请求的权限配置，不是操作系统隔离。组织管理的 hooks 不能由普通设置禁用，见[官方 hooks 说明](https://code.claude.com/docs/en/hooks#disable-or-remove-hooks)；现场启用前须按原有环境验收规则核对有效策略。隔离协议替身只能证明参数和数据流，不能证明真实 CLI 的有效策略或账户权限。

审查只接受严格 JSON：目标哈希与限定范围内的 finding 数组。无效输出、错误哈希、重复 JSON 键、未决或失败运行不能产生通过结论。证据保存实现/审查 run、独立 conversation、后端、配置 revision、原始输入哈希、目标哈希、检查结果及模拟标记。检查前后、审查前后、排队派发前都重新核对目标；通过后 `task.get` / `workflow.evaluate` 再次核对。发现目标变化就作废证据并暂停，不自动将外部修改重新解释为已验收内容。

修复提示词包括原目标、记录的 finding 和检查条件。运行指针、角色、提示词、会话、阶段和预算与操作意图在同一事务提交；审查和修复共用 `max_runs_per_task`，修复还受 `max_repairs` 限制。默认 4 次运行支持“实现、审查、一次修复、再次审查”，不是两轮修复的承诺。已配置 `max_repairs=2` 不会提高总调用预算。所有历史未关闭 finding 都提供给后续 reviewer；通过当前检查与新审查后才记录修复运行和复核证据的关闭关系。

常驻核心空闲时自动推进；一次性 CLI 只推进当次可执行阶段，持续流程使用 `serve` / `--connect` 或常驻 MCP。重启后仅未派发意图可继续；已派发且结果不明的 run 保持待对账，不自动重复调用。人工暂停或取消立即停止后续阶段，保留已有运行终态；当前执行是否终止仍以后端事实为准。流程拥有任务时，直接 `workflow.repair` 或复用实现会话另起任务会拒绝，防止两个编排者竞争。

包版本变为 `0.1.0a3`，SQLite schema 为 4。读取旧 schema 1/2/3 前保存一致快照，旧二进制不能写新运行角色与质量状态。回退必须使用旧库快照的独立副本；保留新记录，先对账在途请求，不用旧意图重发已执行调用。
