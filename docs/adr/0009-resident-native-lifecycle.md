# ADR 0009：本机常驻核心与原生生命周期

日期：2026-09-09。状态：已实现，隔离进程协议验证；真实账户与原生客户端验收仍为 `not_tested`。开发包为 `0.1.0a2`，不表示已发布或部署。

## 进程与入口

`asterun serve` 独占状态目录的 OS 锁和 SQLite 连接，通过权限为 `0600` 的 Unix socket 接受同一用户的 CLI/MCP 语义请求。`--connect` 客户端不再创建第二个执行器；未使用 `--connect` 的第二实例仍被锁拒绝。原生长任务进入后台工作线程，所有状态写入留在核心线程；常驻服务或独立 MCP 的循环持续收取进度，终态落盘不依赖用户轮询。快速、确定性的 fake 脚本保留同步执行。

独立单次 CLI 与 `Application(background=False)` 保留同步兼容方式；需要原生长任务、交互审批或并用多个入口时使用常驻模式。连接模式以服务启动时的配置、主体和运行环境为准，客户端 `--config` 不改变服务配置。当前只支持单用户本机 IPC，不提供 HTTP 或多租户身份边界。

后台进度队列和 IPC 消息有上限。后端调用不持有数据库事务。并发还受按标准化目录建立的工作区互斥约束；同一路径的不同别名或不同后端不能同时写入。等待审批和未知状态继续占用工作区及后端名额。内部互斥不阻止原生客户端或其他程序写文件。

## Codex 接线

在发出 `turn/start` 前，核心确认原生线程引用已落盘。每个 Run 单独保存线程/轮次 ID；后续同 conversation 的任务先核对原生最新轮次与工作区，再恢复相同线程。`session.resume --native` 只核对和恢复，不创建新轮次。发现外部新轮次、路径变化或未结束运行时拒绝自动推进。

常驻连接保留到轮次终态，持续收集公开消息。命令及文件变更审批绑定真实请求 ID、方法、参数摘要、任务和运行，转发前持久化 `forwarding`；断线后不向新连接重发旧审批。批准只对当前请求生效，不自动批准整个会话或扩大永久策略。用户输入、permissions、动态工具等请求仍需专用接口，不能用批准/拒绝冒充支持。

取消先记录请求，由工作线程发出 `turn/interrupt`，收到 `interrupted` 终态后才确认已取消。断线后 `task.reconcile` 只读已保存的确切轮次；没有轮次引用或没有确定终态时保持 `pending_reconcile`，不猜测最新轮次，也不重发任务。退出核心会关闭其原生连接，未决运行保留可对账状态。

协议形状使用本机 `codex-cli 0.153.4` 的 `app-server generate-json-schema` 核对。生成 schema 不启动模型任务。实际往返测试使用仓库内的独立测试进程，不使用真实 CLI 账户或网络；这与真实 Codex/模型服务验收分开。

## 兼容与回退

状态库升级到 schema 3，阻止旧版本丢弃原生引用或误读新审批状态。首次打开 schema 1/2 时，先用 SQLite backup API 保存权限为 `0600` 的 `asterun.schema-<旧版本>.*.sqlite`，成功后才升级；后续打开不重复生成备份。备份恢复入口仍接受 schema 1/2/3 的有效归档。

回退代码前停止核心，保留当前状态和升级前快照。旧二进制只能使用兼容快照的独立副本；不要把旧快照直接覆盖仍有在途任务的状态，也不要因为回退就重发未决操作。升级后新产生的任务不会存在于升级前快照中，必须另外保留和对账。
