# Standard skill entry point

The general Asterun skill lives in `integrations/skills/asterun/`. Copy or package it for a client that supports Agent Skills. Its entry point contains `SKILL.md`, a reference and a Python standard-library helper. The existing core retains execution state, permissions, native sessions, idempotency and recovery. GrokBot chat delivery remains a separate integration.

The Grok terminal-state and occupied-slot recovery fix is available from `0.1.0a15`. Upgrade both core and skill; the minimum interface remains a14, but replacing the skill alone does not repair the old core.

The minimum supported release is `0.1.0a14` for both CLI and resident core. The published a13 wheel lacks compact observation and workflow snapshots. Historical source builds that still report exactly a13 are accepted only after CLI help and read-only resident-interface probes pass. There is no bypass switch. Every operation checks the current resident core; connection failures, timeouts, unknown versions and proven incompatibility remain distinct.

Obtain the core wheel, `asterun-skill-0.1.0a15.zip` and `SHA256SUMS` from the [a15 release page](https://github.com/zonzideka/asterun/releases/tag/v0.1.0a15), verify the download digests, then install each in its appropriate location. Building from a fixed source commit is also supported; retain the core version and source SHA with the skill manifest. The GrokBot release lock still installs published a13, which cannot serve this skill. Its lock is validated and published separately.

Place the skill in the client's discovery directory, such as a Codex project's `.agents/skills/asterun` or the user's skills directory. Preserve an existing skill with the same name. Copying the skill does not install the core, log into accounts or disable MCP. Explicit `$asterun` invocation is available; implicit selection and other clients require separate verification.

Provide the installed CLI, an existing instance state directory and a private evidence directory outside the core state directory. The helper exposes `discover`, `resources`, `scheduler`, `reconcile`, `submit`, `status`, `wait`, `inspect`, `snapshot`, `evaluate`, `repair`, `cancel` and `usage`. Detailed arguments are in the [skill reference](../../integrations/skills/asterun/references/workflow.md).

After compatibility probes, the helper makes one business CLI invocation with `--connect`. It does not open SQLite. Waiting uses the existing compact observer with no events; stdout contains a bounded result and evidence references. Full responses, stderr and requests stay in private files. Evaluation and repair requests reuse the snapshot's complete binding, which the core checks again. The helper does not automatically approve, retry an uncertain mutation, raise budgets or compact a native thread.

`discover` exposes backend execution modes and marks fake backends as simulated. `resources` lists authorized workspace names and locations. A fake-only installation can verify the protocol but cannot generate requested content. Usage detail pagination retains whole-query totals.

For a task that stays queued, use `scheduler` to locate occupying runs, then explicitly `reconcile --task-id ID` for the original task. The core confirms termination only from matching persisted evidence; an acknowledged reconciliation is not acceptance, and unresolved runs retain their slots. Older cores without occupying-run references are marked unavailable. The follow-up core fix dated 2026-10-03 handles a bound incomplete Grok end followed by exit code 1, which older builds misclassified as unknown. That fix is after the published a14 tag and requires a build containing the fix; copying the skill alone does not upgrade the core.

`inspect` saves the CLI response it actually receives. Its 4 MiB parsing limit accommodates JSON that grows when the CLI adds indentation; exceeding this limit preserves the received file and returns `CLI_RESPONSE_TOO_LARGE`. The core socket has a separate 1 MiB message limit. If that limit is exceeded, the core replaces the body with an `INVALID_REQUEST` error, and only that error is saved. The full task body cannot be recovered from this file. Continue observing the original task with compact `status` and read bounded evidence from existing log or artifact paths as needed; repeated inspect calls do not provide pagination.

Execution, acceptance, independent review, termination and delivery remain distinct. Observation deadlines exit with code 124 while the resident task continues. Client timeouts and invalid responses retain the original intent for reconciliation. External reports remain `external_reported` and cannot satisfy independent review.

After committing the skill source, maintainers run `python3 scripts/package-standard-skill.py --output /path/to/asterun-skill.zip`. The fixed member list excludes runtime state; `asterun/manifest.json` records the source commit, `minimum_core_version`, and each member's SHA-256. The core source distribution includes the skill and packaging helper. Installing the core wheel does not install user skills or change client settings. The GrokBot template `0.1.0-rc1` remains pinned to the published `0.1.0a13` wheel, and its chat skills are unchanged. An instance installed from that unchanged lock cannot serve this skill.

Fake tests can measure visible bytes and workflow boundaries. Controller tokens, real model quality, cache behavior and subscription savings require a matched real comparison. A skill does not automatically remove existing MCP tool descriptions. Repository status and the implementation plan record validation and limitations.
