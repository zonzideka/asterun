# 开发规划

[中文](development-plan.md) | [English](en/development-plan.md)

首版以 `0.1.0a13` 已实现的能力为范围，当前源码版本为 `0.1.0a17`。后续工作集中在现有缺陷、兼容性、现场验收和发行文档。核心与三个可选插件采用 Apache-2.0。功能与支持范围见[发行说明](release-v0.1.md)，固定版本的测试和部署结果见 [STATUS](../STATUS.md)。

## 当前维护顺序

2026-10-09 内置 Antigravity 可配置 `timeout_seconds`（30..3600，默认 300）。外部插件源码为 `1.0.2`，其自身 `timeout_seconds` 仍最多 20 秒，并用于 `--print-timeout`。`v*` 发行工作流在 3.11/3.12 离线校验和 main 祖先检查通过后才发布。构建把 `SOURCE_DATE_EPOCH` 设为标签提交时间，并钉死 setuptools 84.0.0 与 wheel 0.48.0。草稿续传沿用已上传资产的来源证明，缺的文件取自同一次 workflow artifact。冒烟会导入依赖并执行入口。流水线尚未对现有标签运行。工具错误仍按原失败语义保留。

2026-10-09 修复结果落盘失败后卡在派发中并占用并发名额、多步写入不在同一事务，以及重启时缺少操作记录仍占名额。失败进入 `pending_reconcile` / `unknown` 并保留结果，不自动重派。同一天补上三处：重试再次失败仍留在内存并按有上限的退避继续写；已释放名额的待对账运行重启后不再占回名额；前台同步派发、取消确认和审批回复走同一结果事务。随后把并发名额收成运行记录上的 `slot_held`，按 run id 幂等投影；审批回复只带回运行中进度时，审批结论仍随这次落盘保存。SQLite schema 6 与对外协议不变。真实后端未验收。

2026-10-09 Codex 普通任务可配置原生 `approval_policy`（`untrusted`、`on-failure`、`on-request`）。省略时仍发送 `untrusted` 与 `workspace-write`。`never`、granular 和关闭沙箱的值在校验时拒绝。固定读取不变。真实 Codex 尚未验收。

2026-10-02 标准 skill 与已发布 `0.1.0a13` 不匹配：将源码标为 `0.1.0a14`，并在 `run.py` 用短超时 `asterun version` / `diagnose` 做失败即拒的最低版本门禁。GrokBot 模板锁仍指向已发布 a13；在 a14 发布并更新该锁之前，模板与标准 skill 不能一起使用。 历史主线构建仍报告 a13 时，仅在 CLI 与应答核心的能力探测全部通过后兼容，规则见[标准 skill](standard-skill.md)。

2026-09-30 按[标准 skill 改造计划](standard-skill-plan-2026-09-30.md)完成通用入口和脚本化机械操作。复用既有 CLI 与常驻核心，标准技能包和用户技能安装不替代核心部署。客户端触发、真实模型质量与 Token/订阅收益保持独立验收，不因离线返回字节减少而修改默认模型、压缩策略或生产配置。

2026-09-24 按[直调复盘计划](grokbuild-direct-retrospective-2026-09-24.md)推进 A00—A03：补齐调用方闭环、编码原生续接、额度停派和受控局部检查。后续检查缓存、异步调度及 A04—A08 保留各自验收门，不把本批离线通过扩展为整个路线图完成或部署完成。

先核对当前提交、工作区改动和相关任务记录，再复现问题。保留已正确实现的协议、原生会话、权限、恢复和质量语义，按实际差量修改。默认验证使用隔离目录和 fake 后端；需要真实账户、部署或外部应用时，按该项任务约定执行。

工作区绑定、固定读取、桌面项目登记、结构化审查状态和收件箱消费者均已有实现。新的维护任务从这些入口复核；具体现场缺口见 [STATUS](../STATUS.md)。Windows、跨主机调度、多租户服务、Web 管理台、公共 HTTP MCP、自动付费路由和市场分发保留为后续候选。

## 修改时保留的契约

配置 v1/v2、SQLite schema 6、冻结 runner-control/v1 和独立 capability profile 各自管理兼容。旧 Task/Run 与标准实体保持各自含义。接口调整应写清输入、返回、旧调用方式和恢复步骤，具体字段以 schema 与当前代码为准。

| 场景 | 检查要求 |
|---|---|
| 身份与资源 | 使用入口建立的主体，执行前核对工作区、动作、账户、运行主机、授权期限和配置 revision |
| 可靠派发 | 先持久保存意图；同键同输入复用原操作，同键异输入返回冲突，落库失败时派发计数为零 |
| 未知结果 | 使用原生引用对账，保留未知状态，后续继续使用原操作关系。名额是否占用只看持久化的 `slot_held`，同一 run id 只投影一次；旧记录没有该标记时，未派发、没有操作或已明确释放的不占名额，其余未结束运行保留预算占位 |
| 会话恢复 | 核对账户、主机、工作区、原生最新轮次和待处理审批 |
| 取消与接管 | 记录请求与后端终止证据；停止后续自动步骤后，再按安全边界交接 |
| 审批 | 绑定实际后端请求、运行、目标和操作摘要；拒绝过期、重复或错位回复 |
| 质量验收 | 检查和 finding 绑定目标版本，独立记录运行、验收、门禁与发布结果 |
| 并发与预算 | 保持唯一编排所有者、有限队列、共享池预留和修复上限 |
| 发布与备份 | 包内运行文件与源码一致；升级前保留一致快照，回退使用对应版本的副本 |

测试、构建和安装依赖属于代码执行。有效授权按原范围复用，新增接收方、费用路径或资源范围时重新匹配。供应商原生权限和操作系统隔离分别验证。

## 提交与验证

每项提交说明具体变更、实际命令和结果、兼容处理及未验证项。测试按纯逻辑、临时目录与协议替身、真实后端、原生客户端四层记录；启动进程、执行项目代码和消费额度的情况一并注明。

默认入口为 `scripts/verify-offline.sh`。针对局部缺陷先运行相关回归，发行内容变更检查 wheel/sdist 成员、正文链接、从 sdist 重建和安装结果。插件来源使用 `python3 packages/asterun-plugin-antigravity/scripts/verify-source.py` 核对。离线入口同时检查 Antigravity 副本是否在未升插件版本时改动。GitHub CI 使用完整历史核对来源提交，并安装插件 wheel 做导入、钉定注册和隔离启动冒烟。

新旧实例切换单独记录任务归属、未决操作、状态快照和回退步骤。调用方应用在各自仓库接线；涉及接口变化时，本仓先提供可复现的参数、返回和交接说明。
