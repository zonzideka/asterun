# Asterun 调优与验收度量规划 v0.1

计划日期：2026-09-07。本文保留尚未执行的实验、首轮采样规模和候选目标。数值用于安排实验，实测性能、SLA 和模型消费预算分别确认。当前实现的运行参数见[安装说明](install.md)，工作项依赖见[开发规划](development-plan.md)。

## 目标与顺序

调优围绕一个合格任务的完成过程，减少等待、返工、资源消耗和人工干预。实验保持相同验收范围、模型质量、授权和持久化要求，完整记录错误与恢复结果。

先在 A1 建立基线与观测，在 A2 测量状态、进程和事件开销，再于 A3 比较工作流及后端组合。A4 验证新用户体验和长期使用。架构调整以测量结果为依据；现有同步和线程实现先作为对照基线。

## 旧实现提供的实验切入点

以下假设来自早期源码观察，现场复现情况待实验确认。文件名引用当时的旧项目；当前代码实验以本仓实现为准，来源范围见[来源说明](source-provenance.md)。

| 编号 | 源码观察 | 实验及候选调整 |
|---|---|---|
| T-01 进程与 RPC | `transport.py` 轮询等待请求响应，stderr 使用管道，读循环处理 stdout | 测量首轮启动、空闲 CPU 和响应延迟；注入大 stderr、EOF、截断 JSON、迟到回复；据结果评估事件唤醒、有界排空和明确关闭 |
| T-02 事件与结果 | Grok session 的 chunk/tool 列表持续追加；Codex recent_events 已限 200 条，消息和轮次另有存储 | 测试长输出和大量工具事件；保留已有截断，评估字节预算窗口、产物文件、游标分页和迟到读者恢复 |
| T-03 归档与恢复 | 已有终态主动归档、幂等集合及 JSONL 全量读取 | 保留由终态触发的主动归档；测量启动扫描、事务写入和结果投影，检查常态查询中的重复全量扫描 |
| T-04 并发与队列 | Claude 已限制进程数；旧公共层缺少持久任务队列与计费池调度 | 测量排队、公平性、取消及过载拒绝，评估有界队列和账户/工作区约束 |
| T-05 完成判定 | 输出可附带 `NodeResult`，完整验收还需其他事实来源 | 固定失败任务和错误自报样例，度量误判完成、漏审和修复收敛；先核对质量门，再比较速度 |
| T-06 配置与连接 | 多处初始化原生进程，配置含作者路径和工具默认位置 | 分开测量发现、认证检查、进程启动和模型首事件；账户/主机/配置指纹相同且隔离验证通过后，再试验连接复用 |

连接复用单独实验。复用范围须满足账户、工作区和权限隔离要求；同一会话的并行轮次按原生后端能力确定。实验同时检查审批串线、取消相互影响和退出后的资源释放。

## 观测记录

每次实验记录 Asterun 提交、配置 revision、Python 与 SQLite 引擎版本、依赖锁哈希、OS/CPU/内存、磁盘类型、实际后端/模型标识、原生 CLI 版本、任务集与输入哈希、并发参数、预算及冷启动状态。账户和计费池使用无秘密的引用，token、cookie 和完整认证文件由原有凭据存储管理。

事件关联 `task_id`、`run_id`、`operation_id`、后端会话/轮次引用及运行内序号。跨进程记录 UTC 时间，同进程耗时使用单调时钟。跨主机延迟计算前先校准时钟。

埋点覆盖请求收到、准入完成、意图提交、进入队列、后端启动、请求发出、首个公开事件、轮次结束、证据持久化、验收结束、取消请求、确认终止和恢复完成。报告拆分 runner、模型推理和人工等待时间。

观测默认保存在用户运行环境。诊断导出由用户选择，导出前脱敏。普通性能日志记录状态、哈希、计数、错误类别和必要引用；源码、提示词及工具原始输入按任务数据管理，公开模型输出按任务数据策略保存，隐藏推理排除在诊断材料之外。

## 指标口径

| 指标 | 计算口径 | 用于判断 |
|---|---|---|
| 首个成功任务时间 | 开始配置至第一个任务验收通过；单列人工登录、下载、模型和 runner 时间 | 初始化是否清楚，是否有重复操作 |
| 准入延迟 | 请求收到至意图提交并返回引用 | CLI/MCP 是否受长任务阻塞 |
| 排队时间 | 准入完成至获得执行槽 | 并发、账户池或审查者的瓶颈 |
| 首事件延迟 | 后端请求发出至第一个公开事件 | 启动开销与后端等待 |
| runner 开销 | 在 fake 场景直接测量准入、调度、规范化、持久化和结果读取 | 各核心阶段的实际开销 |
| 终态可见延迟 | 收到后端终态至终态及关键证据持久可读 | 状态展示滞后和退出丢失结果 |
| 取消确认时间 | 用户请求至可证明的后端终止；另列受理耗时，未确认项单列 | 取消何时实际完成 |
| 恢复对账结果 | 分别计数已证实结果、需人工核对和不可恢复项 | 正确暂停和错误重发 |
| 资源占用 | runner 及子进程分别记录 RSS/CPU；另记打开句柄、队列、事件缓冲、DB/WAL/产物字节 | 泄漏和长输出增长 |
| 验收通过率 | 固定任务集中满足质量门的任务数 / 全部有效尝试；保留失败、超时、取消项 | 同一任务集的完成质量 |
| 修复与人工干预 | 每任务修复轮数、复审次数、人工决策次数及接管原因 | 返工与人工负担 |
| 资源成本 | 各提供方原生 token、次数、订阅窗口、费用及未知项；按可比较单位汇总 | 原口径下的消耗 |

runner 开销通过 fake 直接测量，真实模型总耗时另列。资源成本保留未知值，费用折算需要可验证依据。

## 实验分层与采样

| 层次 | 固定场景 | 首轮采样与报告 |
|---|---|---|
| B0 纯逻辑 | 配置解析、授权匹配、schema 验证、状态转换、revision 冲突 | 固定输入与随机种子，优先检查正确性；微秒差异留在基准报告中 |
| B1 fake 端到端 | 短任务、长输出、审批等待、双入口、慢消费者、重复请求 | 每场景预热 20 次，再采样至少 100 次；实验并发为 1/2/4/8 |
| B2 故障注入 | 意图提交前后、发送后回复前、终态落库前后、进程崩溃、磁盘满、取消竞争 | 每个故障点至少 10 个固定种子；逐类报告结果和重复副作用 |
| B3 长稳态 | 1,000 个顺序 fake 任务，另做至少 30 分钟混合事件负载 | 记录时间序列、资源回收、队列及检查点；报告总事件数和字节数 |
| B4 真实后端 | 纯文本、只读文件摘要、持续会话、中断恢复、取消/审批能力 | 单样例校准后按已授权预算扩样；记录全部失败和不支持项 |
| B5 工作流质量 | 固定小型仓库任务及独立非代码任务，对照后端组合 | 先用 6–10 个任务试验，每条件尽量 3 次；小样本报告逐项结果与中位数，统计显著性留待足够样本验证 |
| B6 用户体验 | 空环境首次任务、跳过可选后端、登录失效、第二次任务、人工接管 | 至少覆盖另一位用户/独立账户环境，保留陌生用户的实际操作记录 |

普通 CI 使用离线、临时目录和 fake 测试，以正确性判断通过。长稳态与计时基准单独触发并记录环境。真实后端单独启用，按授权限制任务量；预算尚未确认时，先准备实验计划和样例清单。实验并发与生产默认值分别维护。

原生兼容矩阵记录“OS + Asterun + 适配器 + CLI/App Server 版本 + 账户方式 + 运行主机”。安装、认证、任务、续接、取消、审批、事件、Desktop 可见性及人工续接逐项给出 `passed / failed / not_tested / not_supported` 和证据。Linux headless 与 macOS Desktop 分别验收。

## 候选性能目标与正确性要求

参考环境为独立的 2 vCPU、8 GiB 内存、本地持久磁盘开发机，供首轮实验复现使用。最低硬件要求另行确认。A1 首次基线后调整候选目标，保留调整依据；绝对延迟在同一环境内比较。

| 项目 | 首轮候选目标 | 测量条件 |
|---|---|---|
| fake 准入延迟 | p95 ≤ 250 ms | 启用持久写，单机并发 4；排除安装、启动和模型时间 |
| 状态与事件第一页 | p95 ≤ 100 ms | 有界页大小，10,000 条历史运行记录；排除远端探测 |
| 终态持久可见 | p95 ≤ 1 s | 从后端终态进入适配器开始计时，由后台完成持久化，直接观测可读状态 |
| runner 额外 RSS | 空闲 ≤ 150 MiB；8 个 fake 活动运行时 ≤ 300 MiB | 原生后端子进程另计，长输出单独报告 |
| 长稳态资源回收 | 预热稳定后，句柄/线程/内存不随已完成任务数线性增长；结束后回到稳定区间 | 磁盘产物按保留策略增长，日志照常保存 |
| 调优收益 | 同环境目标指标改善 ≥ 15%，至少 3 轮复测，质量无退化 | 作为保留性能改动的建议依据；高价值正确性修复单独判断 |

授权旁路、已知重复副作用、错版本验收、关键终态丢失和虚报取消均记为失败。B2 中远端结果无法查清时，暂停并保留证据可通过边界检查，业务结果继续标为未确认。缺少依据的重发或成功上报记为失败。

小样本真实测试报告逐项结果，尾延迟待样本充足后计算。未测量项填写 `not_measured`。

## 候选运行参数

下表保留早期 A3 参数提案，供实验对照。当前默认值以[安装说明](install.md)为准。参数调整经验证后，再写入配置与文档，并遵守用户已授权范围。

| 参数 | 起始提案 | 生效条件 |
|---|---|---|
| 全局活动运行 | 2 | 同时满足后端、账户池和工作区写入约束 |
| 同账户/计费池活动运行 | 1 | 共享关系未知时分别保留原额度；用户声明的关系记录来源 |
| 等待队列上限 | 32 | 满时返回繁忙/可重试，线程创建受界限约束 |
| 同工作区写入者 | 1 | 只读任务也核对输入版本；worktree 用于文件分离，OS 隔离另行配置 |
| 自动修复轮数 | 2 | 每轮重验目标版本，达到上限交还用户 |
| 可安全重试的只读请求 | 最多 2 次，退避并加入随机抖动 | 认证失效后停止重试；限流按后端实际返回处理 |
| 事件查询页 | 默认 100 条，另设总字节上限 | 长输出使用产物文件，游标失效时提供重新对账路径 |
| 取消确认等待 | 首轮观察窗口 15 s | 超时标记待确认/待对账，成功以终止回执为准 |

握手、RPC 响应、任务执行、排队和等待用户输入分别计时。若实验在等待用户时释放执行槽，需同时记录后端会话的资源占用；任务生命周期独立于单次 RPC 超时管理。连接缓存按账户、主机、权限及配置指纹失效。

## 质量与后端组合实验

实施和审查后端通过配置选择。比较使用同一输入版本、相同工具权限、测试集、验收规则和修复上限。

候选 P1 为“已连接的 Grok 实施 + 独立审查”，P2 为“另一较强模型实施 + 相同独立审查要求”。“强模型直接实施”单独记为 P3，按其保障等级评估；省去审查的成本单列，与同等质量下的收益分别报告。运行前核对具体模型 ID、推理设置和实际可用性。

任务集覆盖可机械判定的功能修复、边界条件、依赖/API 变化、无问题审查样例和非 Git 文档任务。固定输入并独立保存验收材料，保留评估答案对实施模型不可见。代码审查按已知缺陷命中与误报评价。

记录端到端完成时间、各阶段等待、全部失败和重试、资源消耗、通过率、引入回归、修复轮数及人工干预。独立裁判的额外调用与费用逐组单列。费用数据可比较时再排序，其余按原单位报告。

修改默认路由前，确认质量要求保持、权限和预算未扩大，并在不同任务上取得稳定收益。变更附实验记录、适用范围、失败回退和配置 revision。充值与 API 付费方式变更另行授权，实验以确认的任务和预算为限。

## 实验产物与维护

原始记录写入被 Git 忽略的本地运行目录，仓库保存脱敏后的实验配置、样例和摘要。报告至少包含 `experiment_id`、基线/候选提交、任务集哈希、环境、样本量、原始记录引用、结果分布、失败原因、质量结论及是否采用。

每轮只改变一个主要因素，例如事件缓冲、轮询策略、事务批次、连接复用或并发。先做小规模对照，出现正确性退化时立即撤销候选配置或代码。数据库升级前验证一致备份可恢复，旧二进制使用其兼容数据库。

SQLite 在线备份使用一致性备份机制，并同时管理 Asterun 产物清单与哈希。运行中的主数据库文件另有 WAL 等状态，完整备份按[SQLite 备份接口](https://sqlite.org/backup.html)处理。

A4 补充保留和清理规则：保留待对账操作及审计证据，清理前检查活动引用。重置范围限定在 Asterun 自有状态，用户原生线程、代码和共享账户继续保留。每次升级回看性能及失败分布，出现新变化或失败证据时再扩大回归范围。
